# 点灯游戏 H22–H68：从 O(n²) 到 O(n^1.585) 的优化与视频交接总结

这是一份可直接交给另一个对话使用的项目背景材料。目标是制作一个新视频：在旧视频的追灯、首行方程和结构化 O(n²) 解法基础上，解释后续各阶段怎样逐步加速，最终把核心求解降到 O(n^log₂3)，约为 O(n^1.585)。

讲解对象只掌握基本线性代数。应先讲“原来重复做了什么、现在怎样少算”，再引入公式和算法名称；不要一开始堆砌商环、Laurent 多项式、half-gcd 等术语。

本文结合现存源码、版本说明和测试记录整理，当前基线为 H68。H63、H64 是后期复杂度突破；H65–H68 继续减少实际运算量。文中的阶段复杂度按源码调用结构分析，不是根据几个计时点拟合出来的。

## 1. 先确定视频中“解出来”指什么

棋盘为 n×n，按一次翻转自己及上下左右的灯，越过边界的邻居不存在。计算在 GF(2) 上进行，只求一个解，不要求按键次数最少。

当前 H 系列的核心基准主要处理**全亮初始棋盘**：目标盘面可以用一句“全亮”描述，不必读入 n² 个灯。程序求出第一行按钮向量 x，并用快速矩阵多项式验证首行方程。

因此本视频主结论是：

> 对全亮目标，求第一行按钮方案并完成首行方程验证，H64 起的核心过程达到 O(n^log₂3)，额外工作空间 O(n)。

第一行确定以后，剩余行都可以追灯生成。如果再显式生成、逐格输出完整 n×n 按钮图，仍要处理 n² 个输出格子。这部分与前述核心复杂度分开计算。任意显式棋盘的输入也有 n² 个数据，不能直接套用“全亮源”的快速 y 公式。

建议视频标题使用“点灯游戏：把首行求解从 O(n²) 加速到 O(n^1.585)”，或在开头明确上述计算范围，然后正常展开核心算法，不必每一节重复强调输出下界。

## 2. 从旧视频接过来的主线

### 2.1 追灯为什么只留下第一行

一旦第一行按法确定，为了消掉第一行剩余的灯，第二行的按法就被唯一确定；第二行确定后，第三行也被确定，依此类推。

所以，原来 n² 个按钮的选择，可以归结为 n 个首行按钮的选择。难点是找到能让最后一行也熄灭的首行。

注意：**试一个首行并追灯需要 O(n²)，枚举全部首行还要乘上 2^n。首行枚举法本身不是 O(n²)。** 后面的多项式方法负责直接求这个首行，消除枚举。

### 2.2 最少需要的数学记号

| 记号 | 通俗含义 |
|---|---|
| n | 棋盘边长 |
| v、x、y、z | 长度为 n 的 0/1 向量 |
| H | 只取左右邻居的矩阵：Hv 的每项是 v 左右两项的异或 |
| J=H+I | 取左、自己、右三项的异或 |
| F_k(t) | 描述递推的 Fibonacci 型多项式 |
| f_n(t)=F_n(t) | H 的特征多项式，满足 f_n(H)=0 |
| c_n(t)=F_n(t+1) | 把首行按法映射到底部残余的多项式 |
| g(t) | gcd(f_n,c_n)，描述奇异性 |
| Q(t) | Bézout 等式中乘在 c_n 前面的多项式 |
| r=deg g | 首行方程的秩亏，不是秩 |

GF(2) 的加法就是异或：0+0=0，0+1=1，1+1=0。减法也等于加法。

多项式的系数可以写成 0/1 串，但要和棋盘行向量区分。例如约定多项式从低次到高次写，`1011` 表示 1+t²+t³；棋盘的 `1011` 表示四个格子的状态。存储形式相似，数学含义不同。

### 2.3 首行方程怎样出现

定义

\[
F_{-1}(t)=0,\quad F_0(t)=1,\quad F_1(t)=t,\qquad
F_k(t)=tF_{k-1}(t)+F_{k-2}(t).
\]

这里采用项目的编号方式，不是把 Fibonacci 多项式从 F₀=0 开始编号。

全亮棋盘的按钮行满足

\[
b_{j+1}=\mathbf1+Jb_j+b_{j-1},\qquad b_0=0,\quad b_1=x.
\]

最后要求虚拟的第 n+1 行按钮为零，可以得到

\[
\boxed{c_n(H)x=y.}
\]

y 就是“第一行不按，直接追灯”所留下的底部残余。它是首行方程的右端项，不是最终按钮方案。

## 3. 完整计算顺序，以及各阶段的职责

实际顺序为 **mak → q → z → x → gen**。讲优化时可以合并 z/gen，但不要让观众以为 gen 在 x 之前运行。

| 阶段 | 做什么 | 为什么需要它 |
|---|---|---|
| mak | 构造 f/c 相关多项式和右端项 y | 准备首行方程 |
| q | 求 gcd 和 Bézout 系数 | 把原方程变成结构更简单的方程 |
| z | 计算 Q(H)y | 得到中间右端项 z |
| x | 求解 g(H)x=z | 恢复一个首行特解，处理奇异情况 |
| gen | 检查 c_n(H)x 是否等于 y | 验证首行方程是否成立 |

为什么 gcd 能帮助求解？扩展欧几里得给出

\[
P(t)f_n(t)+Q(t)c_n(t)=g(t).
\]

把 t 换成 H，并使用 f_n(H)=0：

\[
Q(H)c_n(H)=g(H).
\]

于是可以先算 z=Q(H)y，再进行结构化恢复。g=1 时，g(H)=I，直接有 x=z；g≠1 时，进入奇异恢复。

这解释了 q、z、x 之间的关系。不能把“奇异时取一个普通矩阵逆”作为解释。对于任意右端项，还要考虑可解性；项目最终的 gen 检查也应保留。

## 4. 新旧代码的 f/c 不是同一套记号

这是转交另一个对话时最需要说明的地方。

早期讨论中的 f、c 通常是完整的 F_n(t) 和 F_n(t+1)。H31 以后，利用

\[
u=t^2+t
\]

把 F_n 写成

\[
F_n(t)=A_n(u)+tB_n(u).
\]

由于 (t+1)²+(t+1)=t²+t，同一个 u 在 t→t+1 后不变，因此

\[
F_n(t+1)=A_n(u)+(t+1)B_n(u).
\]

两个长多项式由一对约半长多项式 A、B 表示。当前源码里的 `f`、`c` 主要存储的正是这对 A、B，而不是上面那两个完整多项式。

| 当前代码 | 对应的数学对象 |
|---|---|
| `f` | A_n(u) 的系数 |
| `c` | B_n(u) 的系数 |
| `gu` | G(u)=gcd(A_n,B_n) |
| `qu`、`qv` | 满足 qu·A_n+qv·B_n=G 的 Bézout 系数 |
| `rU` | deg G |
| `r0` | 2 deg G，即完整 g 的次数 r |
| 矩阵 U | H²+H |

这里可以得到一条很统一的数学规律：

\[
\boxed{g(t)=G(t^2+t).}
\]

理由是完整 f、c 相加恰好得到 B(u)，再消去 tB(u) 就得到 A(u)；反过来也能用 A、B 构造 f、c。因此两套多项式的公共因子关系等价。

特别地，r=2 deg G，当前标准方形问题的秩亏是偶数。首行矩阵的秩是 n−r；整个 n² 维棋盘矩阵的秩是 n²−r。不要混用。

若 αA+βB=G，则完整的 Q 可以取

\[
Q(t)=t\alpha(u)+\beta(u).
\]

所以新代码的 z 实际计算

\[
z=[H\,qu(U)+qv(U)]y,
\]

而 gen 检查

\[
[f(U)+(H+I)c(U)]x=y.
\]

这就是“降低多项式规模，同时仍在解原首行方程”。U 与 H 有明确关系，并不是可以随意互换的两个名字。

## 5. mak：怎样从逐项递推变成快速构造

### 5.1 原来慢在哪里

逐项计算第 1、2、…、n 个多项式，第 k 项有 O(k) 个系数，总量为

\[
1+2+\cdots+n=O(n^2).
\]

早期 y 也通过逐层追灯或相关递推构造。只把数组改成滚动存储，会降低空间和复制开销，但不会自动改变这个时间指数。

H30 的原地滚动、H43 的耦合递推、H50 的对称半边递推，主要减少重复写入和重复计算。

### 5.2 H58：Fibonacci 倍增为什么是 O(n)

在 GF(2) 上，有

\[
F_{2k}=(F_k+F_{k-1})^2,\qquad F_{2k+1}=tF_k^2.
\]

平方尤其便宜，因为交叉项全部抵消：

\[
(a+b)^2=a^2+b^2.
\]

例如 (1+t+t³)²=1+t²+t⁶。实现上只是把系数放到偶数下标，空出的奇数下标填零，不需要一般多项式乘法。

计算相邻的一对 F_k、F_{k-1}，即可得到下一层需要的一对。以 32 为例，保留并复用相邻结果：

\[
(F_1,F_0)\to(F_2,F_1)\to(F_4,F_3)
\to(F_8,F_7)\to(F_{16},F_{15})\to F_{32}.
\]

虽然有 log n 层，但每层处理的数组长度不同，总工作量是

\[
n+n/2+n/4+\cdots<2n.
\]

因此递推式是 T(n)=T(n/2)+O(n)，结果为 O(n)，不是 O(n log n)。前提是相邻结果成对求出并复用，不重复递归计算，也不在每个小层都扫描最大容量数组。

**H58 只把 f/c 构造降为 O(n)，当时的 y 仍是 mak 的二次瓶颈。** H60 又把倍增过程改成无分配迭代，进一步减少常数。

### 5.3 H59：y 闭式与全 1 源

先用最直接的方法理解 y。对于 n=5，从两行全零开始，每轮计算

> 新行 = `11111` 异或当前行的“左、自身、右”异或上一行。

依次得到：

| 轮数 | 新行 |
|---|---|
| 1 | `11111` |
| 2 | `10001` |
| 3 | `11011` |
| 4 | `01110` |
| 5 | `10001` |

因此 y=`10001`。朴素做法是算 5 轮；一般规模要算 n 轮，每轮 O(n)。

把这些轮次合并，可以写成

\[
y=S_n(J)\mathbf1,\qquad S_n(t)=\sum_{j=0}^{n-1}F_j(t).
\]

递推式又给出

\[
tS_n(t)=F_n(t)+F_{n-1}(t)+1.
\]

因此不必重新累加 n 个多项式，可以从已有的相邻 Fibonacci 多项式构造出 S_n，再用快速算子处理它。

这里的“除以 t”是**先做精确的多项式除法**，也就是将这个常数项为零的多项式整体降一次幂，再把 t 代成 J。不能直接解释成“求矩阵 J 的逆”，因为 J 可能奇异。

接下来利用输入是全 1。普通卷积每个位置要累加许多乘积；与长度 m 的全 1 串卷积，则只是长度 m 的滑动异或：

\[
c_k=a_k+a_{k-1}+\cdots+a_{k-m+1}.
\]

定义前缀异或 P_k=a_0+…+a_k，便有 c_k=P_k+P_{k-m}，越界前缀视为零。

例如按低次到高次排列，`10110` 与 `111` 卷积得到 `1100010`。原本逐项乘加可以改成前缀异或后取两个端点。

项目还必须处理有限棋盘的反射边界，并构造 Laurent 核；所以不是整个 mak 都降到 O(n)。H59 后首次完整构造为 O(n log n)，其中通用核构造占主要渐近项。H60、H61 又利用 LongWord 和窗口恒等式减少实际操作；当前代码已进一步把部分前缀运算消去，直接读取所需核位置。

## 6. 卷积、Laurent 核与 Karatsuba：z/gen 的共同基础

### 6.1 卷积是“要算什么”，Karatsuba 是“怎样算”

两串系数 a、b 的卷积为

\[
c_k=\bigoplus_{i+j=k}(a_i\land b_j).
\]

这正是多项式乘法的系数计算。

例如

\[
(1+t)(1+t+t^2)=1+t^3,
\]

因为中间的 t、t² 都出现两次，被异或抵消。低次在前时就是 `11` 与 `111` 得到 `1001`。

| 计算办法 | 适用情况 | 典型复杂度 |
|---|---|---|
| 逐项乘加 | 通用卷积 | O(n²) |
| 前缀异或 | 一个乘数是全 1 区间 | O(n) |
| Karatsuba | 通用卷积 | O(n^log₂3) |
| 截断 Karatsuba | 只需要部分系数 | 最坏指数相同，减少无用计算 |
| 反射对称拆分 | 输入有已知对称性 | 缩短乘数，降低常数 |

所以“使用卷积”本身不保证复杂度下降；还要看卷积的结构及具体计算方法。

### 6.2 为什么 p(H)v 能变成卷积

H 的作用是左右移位后异或。在不考虑边界的无限直线上，可用一个移位符号 s 表示右移，用 s⁻¹ 表示左移：

\[
H\longleftrightarrow s+s^{-1}.
\]

于是 p(H) 对应 p(s+s⁻¹)。展开后，每个系数表示“把输入移动多少格，再异或进结果”。这串移位系数就是卷积核。允许负指数的表达式称为 Laurent 多项式；负指数在这里仅表示向相反方向移动。

若使用 U=H²+H，对应的无限直线表达式为

\[
s^2+s+s^{-1}+s^{-2}.
\]

**有限棋盘必须另行处理边界。** 不能把无限直线卷积截取一下，就认定所有 p(H)v 都算对了。代码采用反射、循环嵌入、核折叠和有效窗口，恢复有限路径矩阵的真实作用。

也不要说“任何 p(H) 都是 Toeplitz 矩阵”：边界会产生修正。Toeplitz 的含义是每条斜对角线上的数相同，它解释了卷积结构；但要连同边界结构一起使用。

### 6.3 H40：Karatsuba 怎样改变指数

将两个多项式各分成两半：

\[
A=A_0+t^mA_1,\qquad B=B_0+t^mB_1.
\]

直接展开要算四次半长乘法。Karatsuba 只算三次：

\[
P_0=A_0B_0,\quad P_2=A_1B_1,\quad
P_1=(A_0+A_1)(B_0+B_1).
\]

中间项由 P₁+P₀+P₂ 恢复，所以

\[
AB=P_0+t^m(P_1+P_0+P_2)+t^{2m}P_2.
\]

每层三次半长乘法，加上线性异或：

\[
M(n)=3M(n/2)+O(n)=O(n^{\log_2 3}).
\]

1.585 来自 log₂3≈1.5849625，正式推导应使用 log₂3。

Karatsuba 等 GF(2) 多项式乘法属于已有算法；项目的工作是把点灯中的矩阵多项式作用转成适用的卷积，并处理边界、对称性和数据布局。相关背景可参阅 Brent 等人的 [Faster Multiplication in GF(2)[x]](https://maths-people.anu.edu.au/brent/pd/rpb232tr.pdf)。

### 6.4 为什么 z 与 gen 经常一起变快

z 计算 Q(H)y，gen 计算 c_n(H)x。两者多项式和输入不同，却共用快速矩阵多项式算子。

因此，改进 Laurent 核构造、Karatsuba、反射窗口等公共过程，会同时改善 z 和 gen。gen 的数学任务仍是检查原方程，不能为缩短时间而减少检查条件。

| 版本 | z/gen 的主要改进 |
|---|---|
| H25–H26、H32、H35–H39 | 压缩表示、融合算子、减少重复推进及位访问开销 |
| H40 | 引入 Karatsuba，形成通用乘法的次二次路线 |
| H41–H42 | 融合 Laurent 核；利用反射把长卷积改写成半长计算 |
| H44–H48 | 成对乘法复用分裂；跳过零分支；按实际长度递归；改进核构造及叶节点 |
| H49 | 消除 z 中重复的卷积计算 |
| H53–H54、H57 | 融合核平移，保留必要窗口，区分内部区与边界区 |
| H61 | 进一步优化 B 版 Laurent 叶节点与合并 |
| H66 | gen 检查实际输入是否对称，对称时复用相同乘积 |
| H67 | 减少 Karatsuba 重叠区合并的异或 |
| H68 | 在已有对称压缩上，再改成两次约半长乘法 |

H68 的主项从 M(n) 变成 2M(n/2)，对 Karatsuba 来说约为原来的 2/3。它降低常数，不再降低复杂度指数。奇异问题求得的特解 x 未必对称，因此 gen 会检查实际对称性；非对称输入仍完整计算。

## 7. q：从欧几里得长除法到 half-gcd

### 7.1 早期优化主要是缩小规模和减少更新

普通整数有辗转相除法，多项式也一样：用除法不断把一对多项式变成“除数和余数”。同时记录每个余式由原输入怎样组合，就得到 Bézout 系数。

旧版每消去一个最高项，都可能扫描一长段系数。累计起来，最坏为 O(n²)。

| 版本 | q 的改进 | 是否改变二次指数 |
|---|---|---|
| H24 | 减少 Bézout 相关维护和恢复开销 | 否 |
| H31 | u=t²+t 分解，约半长的 A、B 代替完整 f、c | 否 |
| H33–H34 | 利用 Fibonacci 奇偶提升进一步降阶 | 否 |
| H47、H52、H55–H56 | 单乘积恢复、融合移位更新、无分支异或等 | 否 |
| H62 正式修订版 | 连续 Fibonacci 降阶及 Bézout 提升 | 否 |
| H63 | half-gcd、快速除法及快速 Bézout 恢复 | 是 |
| H65、H67 | 截断乘法、余式次数界和融合更新 | 保持新指数，继续减少运算 |

早期被否定的 H62 慢版不能和正式修订 H62 混为一谈。一次标为“快速 gcd”的实验变慢，也不能证明成熟 half-gcd 的理论不成立；需要检查分治结构、乘法、除法及系数恢复是否都已经加速。

### 7.2 快速除法：先求一个多项式的倒数

普通长除法从最高次逐项消去。把系数顺序反转后，求商可以转成：

> 求除数的形式幂级数倒数，再做一次截断乘法，最后反转回来。

“形式幂级数倒数”只要求前 k 个系数正确，并不涉及实数小数的近似误差。

若 A 的常数项为 1，已有 G 满足 AG≡1 mod t^k，在 GF(2) 上可以更新

\[
\boxed{G_{\rm new}=AG^2\pmod{t^{2k}}.}
\]

因为 AG=1+E，E 的前 k 项为零，那么

\[
AG_{\rm new}=(AG)^2=(1+E)^2=1+E^2,
\]

误差从第 k 项推到第 2k 项以后。因此每轮正确项数翻倍。这是特征二域下 Newton 求逆的简化形式，不是数值试探。

其代价为 I(n)=I(n/2)+O(M(n))，所以 I(n)=O(M(n))。

### 7.3 half-gcd：一次压缩一串消元步骤

一次欧几里得步骤可以写成一个很小的“多项式矩阵”：

\[
\begin{pmatrix}a\\b\end{pmatrix}
\longmapsto
\begin{pmatrix}0&1\\1&q\end{pmatrix}
\begin{pmatrix}a\\b\end{pmatrix}.
\]

half-gcd 先看高位部分，递归求出一串合法步骤的合成矩阵，再用快速乘法将这些步骤一起应用到完整多项式上，使余式次数大约降到一半，然后继续。

它不是“把多项式低位扔掉求 gcd”，也不是“普通 Euclid 每次少算一半”。高位用来确定成批变换，完整数据仍经过正确的更新。

half-gcd 是已有快速多项式算法。其通用复杂度常写成 O(M(n) log n)；针对项目的 Karatsuba 乘法，可以利用更具体的递归式得到更紧的界。有关算法背景见 van der Hoeven 的 [Optimizing the half-gcd algorithm](https://arxiv.org/pdf/2212.12389)；下述具体合并分析针对本项目的乘法增长率，不等于照搬该论文的 FFT 实现。

设 α=log₂3，则

\[
D(n)\le 2D(n/2)+O(n^\alpha).
\]

第 j 层的非递归工作量为

\[
O\!\left(n^\alpha(2/2^\alpha)^j\right)
=O\!\left(n^\alpha(2/3)^j\right).
\]

各层构成递减等比数列，总和 O(n^α)，不用再额外乘 log n。完整扩展 gcd 和 Bézout 恢复也必须使用快速乘法，才能保持这个界。

固定大小的递归叶节点使用普通消元，不影响渐近指数；这和为某几个测试规模预存答案不是一回事。

## 8. x：从带状回代到快速三角除法

### 8.1 旧方法已经比普通高斯好得多

g(H) 具有带状结构，最远作用距离由 r=deg g 决定。H23 等早期版本利用结构避免大量重复工作，x 的实际用时大幅下降；H51 又使用固定 Laurent 核和 32 系数分块。

但如果仍逐项回代，每项要更新约 r 个位置，常用上界还是 O(nr)。当 r 随 n 成比例增长时，最坏仍可能二次。

需要纠正一个细节：r=n 在当前恢复中意味着没有待解的有效段，可以直接退出，未必最耗时。二次工作量可能出现在 r 与 n−r 都为 Θ(n) 的情形。视频可以讲“最坏 r 不能当常数”，不要把“r=n”说成必然最慢的具体输入。

### 8.2 H64 把回代改成卷积除法

选定自由变量之后，待解部分具有三角 Toeplitz 结构：沿斜对角线重复使用同一个核。把合适的顺序反转，就可以写成

\[
D(t)X(t)=R(t)\pmod{t^\ell},\qquad \ell=n-r,\quad D(0)=1.
\]

通俗地说，旧方法是“解出一个值，就把它的影响逐个传给后面”；新方法是“把这套重复影响写成固定卷积核，利用核的倒数成块求解”。

H64 使用 Newton 求逆和分块 Karatsuba。它与 q 共享了快速多项式乘除法的工具，但所解的是不同问题：q 求 gcd/Bézout，x 求结构化三角系统。

取有效核长度 d=min(2r+1,ℓ)，非退化情况下，主要工作可以界为

\[
O\!\left(n+r\log r+(1+\ell/d)M(d)\right).
\]

由于 M(d)=O(d^α)，分块部分约为 ℓd^(α−1)，且 ℓ、d≤n，因此最坏不超过 O(n^α)。退化情形单独直接处理。

**H64 是把最后一个可能二次的核心阶段也改成次二次计算的关键版本。** 对通常秩亏较小的 n，旧回代原本就很便宜，不能保证每一个规模都出现巨大时间下降。

## 9. 把四个阶段的复杂度合起来

以下按单个规模 n、全亮源、首行求解与快速验证计算，令 α=log₂3。

| 阶段 | 旧的主要工作 | H64–H68 的主要工作 | 当前上界 |
|---|---|---|---|
| mak | 逐项构造多项式和 y | f/c 倍增；y 闭式、核构造与全 1 源处理 | O(n log n) |
| q | 朴素扩展 Euclid | half-gcd、快速除法、Bézout 恢复 | O(n^α) |
| z/gen | 多次对 n 维向量应用 H 或 U | Laurent 核、边界变换、Karatsuba | O(n^α) |
| x | 带状回代 O(nr) | 固定核、Newton 求逆、分块卷积除法 | 最坏 O(n^α) |

这些阶段是顺序执行，复杂度相加，不相乘：

\[
T(n)=O(n\log n)+O(n^\alpha)+O(n^\alpha)+O(n^\alpha)
=O(n^\alpha).
\]

主定理可以在视频结尾用三条递推做总结：

| 子过程 | 递推关系 | 结果 |
|---|---|---|
| Fibonacci 倍增 | T(n)=T(n/2)+O(n) | O(n) |
| Laurent 核分治构造 | T(n)=2T(n/2)+O(n) | O(n log n) |
| Karatsuba | T(n)=3T(n/2)+O(n) | O(n^log₂3) |
| half-gcd 的主要递归 | T(n)≤2T(n/2)+O(n^log₂3) | O(n^log₂3) |
| Newton 精度倍增 | T(n)=T(n/2)+O(n^log₂3) | O(n^log₂3) |

直观区别是：每层工作量相同时才容易出现 log n 因子；各层按比例递减时，应把等比数列求和，不能看到递归深度 log n 就直接乘上去。

工作空间 O(n) 来自滚动数组、深度优先递归和临时区回收。递归深度为 log n，不代表必须同时保存 log n 份最大长度数组。

另一个计量问题：单次求规模 n，和从 1 到 N 每个规模都从头求一遍，不是同一任务。后者一般要计算 ∑n^α=O(N^(α+1))；标准测试的 9900..10000 是固定 101 次调用。

## 10. H65–H68：指数不变，还能怎样继续优化

| 版本 | 实际保留的改动 | 主要阶段 | 性质 |
|---|---|---|---|
| H65 | 成对截断乘法，利用欧几里得余式次数界只计算必要系数 | q 为主 | 少算不需要的乘积系数，指数不变 |

## 12. 推荐的视频章节顺序

1. **旧视频回顾**：追灯、只求首行、原来的 O(n²) 结构化解法。说明一次追灯与首行枚举的区别。
2. **一张流程图**：mak→q→z→x→gen，解释每个阶段要交付什么。
3. **最少的多项式知识**：系数串、异或、移位、递推、p(H)v；说明矩阵只需作为算子存在，不必真的存出来。
4. **先拿下容易理解的 mak**：Fibonacci 倍增与平方插零；相邻结果复用；n+n/2+…为何是 O(n)。
5. **介绍卷积，再解释 y**：全 1 源为什么变成滑动异或；闭式怎样省去逐轮追灯。Laurent 与有限边界先给直观图，细节稍后展开。
6. **通用乘法工具**：Karatsuba 的“四次变三次”，第一次推导 1.585。
7. **完成 q 这条线**：先讲原始 gcd/Bézout 的作用，再讲 u=t²+t 降阶；之后讲精确 Newton 求逆、快速除法、half-gcd。
8. **回到 z/gen**：详细展示 p(H)v→Laurent 核→反射边界→卷积；解释半长、复用和窗口，以及为何两个阶段常同步变快。
9. **处理最后的 x**：秩亏和自由变量；旧带状回代；三角 Toeplitz；复用前面已经讲过的快速除法工具。
10. **汇总与实测**：四阶段复杂度表，主定理/递归树，A/B 分阶段耗时。区分指数变化和常数变化。
11. **可选展望**：Toom-Cook、FFT、商环路线，明确哪些尚未在正式版采用。

严格按照程序执行顺序逐个引入所有知识，会使 q 一节突然依赖尚未讲过的快速乘法。更适合采用“先给执行总览，再预讲公共工具，最后按阶段展开”的方式。

Lucas 定理可以作为 Fibonacci 系数图案的补充；商环可以作为 f_n(H)=0 的统一解释；Toom-Cook 和 FFT 放在尾声。它们都不应打断主线。

## 13. 可以顺带讲的数学知识

- **Lucas 定理的二进制直觉**：二项式系数模 2 的奇偶由二进制位决定，可解释 Fibonacci 多项式中的规则图案。但图案规律本身不等于已经实现一个更快的求解器。
- **Horner 法**：p(H)v 可写成不断“乘 H 再加一项”的嵌套式，减少重复求幂；若仍做 n 次长度 n 的推进，依然是 O(n²)。
- **Cayley–Hamilton 与商环**：f_n(H)=0 意味着多项式相差一个 f_n 的倍数，代入 H 后作用相同。于是可以用除以 f_n 的余式代表同一个矩阵算子。商环是组织这些等价类的语言，不是“把 H 设成零”。
- **Toeplitz 与卷积**：斜对角线相同，使同一套系数在不同位置重复作用。三角情形又对应逐项可解的卷积除法。
- **秩亏与 gcd**：g 的次数告诉我们有多少自由维度。当前具有 gcd(A,B) 与 g(t)=G(t²+t) 的统一关系，但不能据此宣称已找到只依赖 n 的简单 gcd 通项且不必计算。
- **分治与主定理**：不仅要数层数，还要数每层子问题的数量、规模及合并成本。
- **Toom-Cook/FFT 的适用域**：在 GF(2) 中，1=−1，普通 Toom-3 的一些求值点会重合，某些除法不可用；不能把整数版公式直接照搬。它们是后续研究方向，不是当前 1.585 结论的依据。

## 14. 交给下一对话时必须保留的约束

1. 用户希望讲解简单、例子具体，数学基础按基本线性代数处理。
2. A 版使用 Boolean，B 版使用 LongWord；数学公式、恢复方式及验证条件必须一致。B 的优势是并行处理同一批系数，不是更换算法。
3. A/B 耗时比不是固定 20 或 32。阶段变成小规模、线性构造后，调用、边界和访存开销会占更大比例。不能通过拖慢 A 来“恢复比例”。
4. 复杂度下降与实测提速必须分别说明。n=10000 的常数收益，不等于证明指数下降；渐近改进，也不保证每个 n 都更快。
5. 禁止使用编译器优化指令制造算法收益。保留分阶段计时，所有实际 mak 计算仍应纳入对应计时；预热与冷启动数据须注明口径。当前源码另有一次计时前的 MakeMat 预热，正式计时调用仍重新执行计算，不应将其描述为仅分配内存。
6. 标准 A/B 测试为 n=9900..10000；标准 a_out 是 n=1..20 的文本诊断，图片版是单独的输出版本。
7. 修改要小、可追踪，保留 CRLF 和惯用文件名；新版本附一行说明。不能以重命名或说明文字代替真实改动。
8. gen 通过是必要证据，但共享算子的 bug 可能同时影响计算和验证，应继续保留独立追灯或独立小规模矩阵检查。
