我完整核对了“最初对话”、版本说明、H40–H58 源码、`all_results` 汇总表和逐行运行日志。最重要的结论是：

> 理论算法主线仍然成立，H41–H58 的大部分优化方向也确实落到了代码中；但当前 H58 不能视为合格的 A/B 共同版本，因为 A 版从 H43 开始出现正确性回归。现有日志中，最后一个 A、B 都全部通过验证的版本是 H42。

## 一、最初对话是怎样开始的

你最初的问题是：

> 寻找标准 N×N 点灯游戏时间复杂度最低的通用算法，不允许针对每个 N 预先计算，允许 n 推 n+1，只求任意特解，不要求最少步。

最初讨论经历了几个阶段。

| 阶段      | 主要内容                                        | 最终认识                                                                 |
| ------- | ------------------------------------------- | -------------------------------------------------------------------- |
| 第一轮搜索   | 比较首行穷举、全局高斯、首行方程、zero-forcing、Fibonacci 多项式 | 推测可以利用多项式同余和扩展 Euclid 达到 O(n²)                                       |
| 你的第一次质疑 | 追问是否有文献明确给出 O(n²)，还是 AI 自行推导                | 承认最初的“商环 + Euclid”是基于文献结构的自行推导，不是论文原文结论                              |
| 第二轮搜索   | 找到 axpokl 的 Pascal 点灯算法和 O(n²) 说明           | 获得一条独立、可运行的 O(n²) 实现路线                                               |
| 代码审计    | 检查奇异情况、Euclid、隐藏复杂度、预计算、输出范围                | 确认核心算法确实没有隐藏 O(n³)，但现成程序主要针对固定全亮目标和第一行核心方程                           |
| 算法比较    | 比较 axpokl 的 `g(H)` 回代与商环除 gcd 求逆            | 两者数学核心相同，奇异情况处理方式不同                                                  |
| H40 审计  | 阅读全部版本和性能结果                                 | 确认 H6 已形成 O(n²) 框架，H15 后空间 O(n)，H31 后进入 U 降阶路线，H40 在 A 版启用 Karatsuba |

最终形成的理论结论是：

* 对任意显式 N×N 盘面，读取输入和完整输出都需要 Ω(n²)。
* 利用追灯、多项式、gcd/扩展 Euclid 和结构化奇异恢复，可以做到 O(n²)。
* 因而完整通用问题可以达到 Θ(n²) 时间、O(n) 工作空间。
* 但 H 系列基准程序本身主要是固定全亮目标、求第一行并验证核心方程，并不是已经完成的任意棋盘输入接口。

## 二、目前算法的数学结构

当前 H58 仍然延续 H31 以后形成的主线，并没有改成最初设想的完整商环求解器。

设 H 是一行上的左右邻接算子：

$$
(Hv)_i=v_{i-1}\oplus v_{i+1}
$$

再定义：

$$
U=H^2+H
$$

Fibonacci 型多项式可写成：

$$
F_n(x)=A_n(x^2+x)+xB_n(x^2+x)
$$

当前代码中的变量含义是：

| 变量        | 数学含义                       |
| --------- | -------------------------- |
| `f`       | \(A_n(U)\)                 |
| `c`       | \(B_n(U)\)                 |
| `gu`      | \(G(U)=\gcd(A_n,B_n)\)     |
| `qu,qv`   | 对应的 Bézout 系数              |
| `rU`      | \(G(U)\) 的次数               |
| `r0=2*rU` | 完整 gcd 次数，也对应秩缺陷           |
| `y`       | 固定全亮目标追灯后形成的首行方程右端项        |
| `z`       | Bézout 多项式作用在 `y` 上得到的中间向量 |
| `x`       | 求出的第一行按钮向量                 |

当前完整流程为：

| 计时阶段  | 当前工作                                         |
| ----- | -------------------------------------------- |
| `mak` | 构造目标向量 `y`、当前规模的 `f,c,f1,c1` 和半规模缓存          |
| `q`   | 利用偶数/奇数提升先缩小规模，再执行 `GcdU` 求 `gu,qu,qv`       |
| `z`   | 通过 Laurent 核、反射对称和 Karatsuba 计算 Bézout 多项式作用 |
| `x`   | `r0=0` 时直接令 `x=z`；奇异时仍求解 `g(H)x=z`           |
| `gen` | 再次使用快速多项式作用，验证 \(F_n(H+I)x=y\)               |

因此当前算法仍是：

$$
\gcd+\;g(H)x=z+\text{结构化奇异恢复}
$$

而不是完整的：

$$
cU\equiv Q\pmod f
\rightarrow g\mid Q
\rightarrow \frac c g,\frac f g,\frac Q g
\rightarrow \text{统一模逆}
$$

最初尝试的商环 H41 因实际耗时恶化、尤其 z 明显上升而被放弃；源码包中最终保留下来的 H41 已经不是商环版，而是 Laurent/Karatsuba 优化版。

## 三、最初确定的四条深层优化路线

当时总结的四条路线是：

| 路线            | 目标                          | 当前完成度                                    |
| ------------- | --------------------------- | ---------------------------------------- |
| 快速构造 `f,c`    | 利用 Fibonacci 倍增，避免逐 n 的二次累计 | H58 已开始实现，`f/c` 构造降为 O(n)                |
| 快速 gcd/extgcd | 用 half-gcd 等替代朴素 Euclid     | 尚未完成；H52、H55、H56只是降低常数                   |
| 快速多项式作用       | 加速 `q(H)y`、`g(H)e₀` 和验证     | H40–H54 的主要成果，已大量使用 Karatsuba/Laurent 卷积 |
| 快速基变换         | 在普通向量基与商环多项式基之间快速转换         | 尚未形成完整实现，也是商环路线的主要障碍                     |

所以 H41–H58 的实际优化主要集中在第三条，其次处理 `q`、奇异 `x` 和第一条 `mak`。

## 四、H41–H58 的优化情况

| 版本  | 主要改动                                | 主要影响阶段                       |
| --- | ----------------------------------- | ---------------------------- |
| H41 | 融合 Laurent 核构造，缩小 Karatsuba 叶节点     | z、gen                        |
| H42 | 利用反射对称，把一次全长卷积改成两次半长卷积              | z、gen 显著下降                   |

| H44 | 将两次 Karatsuba 卷积融合，复用分裂与异或          | z、gen                        |
| H45 | 按有效长度跳过补零递归                         | z、gen                        |
| H46 | 从二次幂补零改成实际长度的非等长递归                  | z、gen                        |
| H47 | 用一次 Bézout 系数乘法恢复另一系数，并采用32系数分块     | q                            |
| H48 | Laurent 核递归消除零填充，统一256位叶节点          | z、gen                        |
| H49 | 合并 z 阶段两个相同的 Karatsuba 卷积           | z；但 A 版101组全部失败              |
| H50 | `y` 只递推半边，再镜像展开；B 版用 LongWord 反转    | mak                          |

| H52 | 融合 Euclid 同位移的余式和 Bézout 更新，加速最高位查找 | q                            |
| H53 | 融合 Laurent 子核四路平移，直接折叠保留半核          | z                            |
| H54 | 循环折叠改成只抽取最终需要的窗口                    | B 版 z                        |

| H57 | 拆分 Karatsuba 固定公共区和边界区              | z、gen，小幅改善                   |

## 六、当前发现的正确性问题

逐行日志给出的结果非常明确：

| 版本范围    |      A 版验证 |      B 版验证 | 判断            |
| ------- | ---------: | ---------: | ------------- |
| H22–H42 | 101/101 通过 | 101/101 通过 | 当前最后的共同正确基线   |
| H43–H48 |  60/101 通过 | 101/101 通过 | A 版开始回归       |
| H49     |   0/101 通过 | 101/101 通过 | A 版完全失败       |
| H50–H58 |  65/101 通过 | 101/101 通过 | A 版部分恢复，但仍不正确 |

错误首次出现在 H42→H43。该版 A 版大改了 `MakeMat`，新增 Boolean 版 `BuildYFast`、`BuildFCFast` 和双缓冲；B 版此时只做了很小的等价化简，而且仍全部通过。因此问题范围已经可以定位到：

* H43 的 A 版 `MakeMat/BuildYFast/BuildFCFast` 移植；
* Boolean 局部缓冲和高边界初始化尤其可疑；
* H44–H58 都继承了这条错误的 A 版基础。

另一个问题是 `all_results.ps1` 的正则表达式同时接受 `gTRUE` 和 `gFALSE`，汇总时没有拒绝或排除失败行，所以错误版本仍被写进性能表。这也是为什么单看 Excel 会误以为 H43–H58 都是正常版本。

因此，按照你后来制定的要求，当前应当这样认定：

* H42：最后一个日志确认的 A/B 共同正确版本。
* H58 B：独立验证通过、性能很好，但不能单独作为项目最终版本。
* H58 A：不合格。
* H43–H58 的优化思想可以保留，但必须在修复 A 版后重新验证，不能直接以 H58 为正确基线继续 H59。

## 七、你后来逐步追加的详细要求

这些要求并不是一次提出的，而是在发现版本分叉、B 版退化、说明与代码不一致等问题后逐渐加严的。

| 类别        | 详细要求                                                            |
| --------- | --------------------------------------------------------------- |
| 问题边界      | 必须针对一般 N；不允许保存每个 N 的预计算逆矩阵或答案；允许由 n 推 n+1；只求任意特解，不求最少步          |
| 复杂度表述     | 必须区分整体复杂度和局部复杂度；Karatsuba 加速一个阶段，不能据此声称整个算法已经变成 O(n¹·⁵⁸⁵)       |
| 证据等级      | 必须区分“论文明确结论”“从源码可审计确认”“我们自行推导、尚需验证”三种层级                         |
| A/B 数学一致  | A、B 每一步必须采用完全相同的数学算法、分支条件、递推结构和奇异处理                             |
| A/B 实现定位  | A 版每个系数用 Boolean；B 版只是把同一批系数压成 LongWord 并行计算，不能成为另一套算法          |
| 禁止算法分叉    | 不能 A 用 Karatsuba、B 用另一种结构后仍称两版一致；若某路线不能同时用于两版，应选择共同最快的路线或放弃     |
| 禁止按 N 选算法 | 不允许为了跑分根据 N、奇偶或阈值选择本质不同的求解算法；数学上固有的奇偶递推除外                       |
| 同步原则      | 不能靠重命名或机械复制宣称同步；必须确认 `mak/q/z/x/gen` 每个阶段计算的是同一个数学对象            |
| 正确性优先     | 只有输出正确后才比较性能；任何 `gFALSE` 都应使该版本测试失败，不能继续参与正式汇总                  |
| 奇异情况      | 不能只验证 `g=1`；必须覆盖 `g≠1`、不同 `deg(g)`、反向消元或分块除法等路径                 |
| B 版速度优势   | B 应保留 LongWord 带来的显著优势；如果 z、gen 等突然慢十倍、接近 A 版，说明位并行结构可能被破坏      |
| A/B 比例    | 比例不是固定必须大于20，但若从以往水平明显降到20以下，必须解释是 A 真正改善，还是 B 退化或两版算法不一致       |
| 阶段计时      | 必须分别观察 `mak、q、z、x、gen`，不能只看总时间                                  |
| 优化优先级     | 早期重点是 q、z、x；H44 后允许在保证正确性的前提下优化全部五个阶段                           |
| 不接受明显倒退   | 特别是 z 曾因商环实验显著上升，这种理论上更漂亮、实测却更慢的方案不应保留                          |
| 预测影响      | 提出新版本前，应说明预计会影响哪个阶段，哪些阶段理论上应不变，避免跑完后才解释                         |
| 真实算法改进    | 优先降低运算次数、有效长度或复杂度；希望向 Karatsuba、half-gcd、倍增、O(n log n) 等方向推进    |
| 编译器限制     | 禁止通过 `{$optimization on}` 等编译器指令制造提升；`inline` 可以使用，但不能把它包装成算法突破 |
| 商环路线条件    | 商环并非禁止，但只有在实际能够降低时间、同时维持 A/B 一致时才采用；不能只因形式统一而接受性能倒退             |
| gen 的特殊地位 | gen 是验证阶段，原则上尽量不修改；若 z/gen 共用核心算子而必须一起优化，应证明验证语义没有变化            |
| 修改范围      | 每版尽可能只改一个明确方向；少改原代码，便于比较、回滚和定位问题                                |
| 代码格式      | 保留原 Pascal 排版、命名和 Windows CRLF，不增加无关空行，不进行大规模风格重写               |
| 基线选择      | 出现错误分支后，应回到最后一个确认正确且速度好的版本重新移植，不能在错误版本上继续叠加                     |
| 版本真实性     | 新编号必须有真实代码变化；不能出现 H42/H43 文件实质相同、版本说明却声称不同优化的情况                 |
| 性能波动      | 小幅变化可能只是运行波动；若提升不明显，应如实说明。你可以决定“保留但不认为是显著提升”                    |
| 一次成功率     | 后来你强调使用量有限，希望每次先充分分析再改，尽可能避免试错式连发版本                             |
| 交付组成      | 新版通常需要 A、B、`out` 等对应文件，并打包为 ZIP；文件名必须带正确 H 版本号                  |
| 大规模正确性输出  | 曾明确要求 H42 A/B 在 T1000、T10000 生成对应 `_out`/PNG 结果，用于大规模交叉验证       |
| 版本说明      | 每版需要一行说明：文件名、方法、时间复杂度、空间复杂度、具体变化                                |
| Excel     | 通常不要求我直接更新版本说明 Excel，但要提供可以填入表格的准确文字                            |
| gen/输出一致  | 标准版、A/B版和 `_out` 版不能各自停留在不同算法版本，否则验证不能代表正式代码                    |
| 通用性表述     | 必须明确“数学上可以扩展到任意盘面”与“当前程序已经实现任意盘面接口”不是一回事                        |

## 最终判断

目前最准确的项目状态是：

1. Θ(n²) 时间、O(n) 工作空间的理论主线成立。
2. 当前仍采用 `gcd + g(H)结构恢复`，没有完成商环统一求解。
3. H41–H58 已经覆盖 Laurent/Karatsuba、反射、非等长递归、Euclid 融合、分块奇异恢复和 Fibonacci 倍增等多个方向。
4. B 版的性能提升非常明显，而且 H58 日志全部正确。
5. A 版从 H43 开始错误，说明后来最重要的“A/B数学完全一致”要求实际上没有被满足。
6. 因而目前可靠的共同基线应退回 H42；H43–H58 的优化应逐项重新移植和验证，而不能直接继续 H59。
