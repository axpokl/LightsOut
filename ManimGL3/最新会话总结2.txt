我正在制作一个新的“点灯游戏 / Flip Game”算法视频，重点解释如何把旧视频中首行求解核心的 **O(n²)** 逐步优化到大约

# 四、当前统一数学记号

工作域：

`GF(2)`

所以：

`+ = XOR`

即常写作：

`⊕`

矩阵：

`H`：原来的左右扩散矩阵。

`J=H+I`

因此 J 作用到一个向量，相当于：

> 左移一份 + 原位一份 + 右移一份，然后 XOR。

目前讲稿里有时写行向量、有时写列向量，暂时不用纠结，最后统一即可。

# 五、Fibonacci 多项式的固定定义

这一套下标不能改变：

`F₀=1`

`F₁=t`

`Fₙ=tFₙ₋₁+Fₙ₋₂`

所以：

`F₂=t²+1`

`F₃=t³`

`F₄=t⁴+t²+1`

`F₅=t⁵+t`

倍增公式：

`F₂ₖ=(Fₖ+Fₖ₋₁)²`

`F₂ₖ₊₁=tFₖ²`

利用 GF(2) 的 Frobenius 性质：

`(A+B)²=A²+B²`

平方只需要把多项式各项指数翻倍，所以相邻 Fibonacci 多项式可以快速生成。

这里曾经介绍过：

`u=t²+t`

以及

`f=A(u)+tB(u)`

`c=A(u)+(t+1)B(u)`

目前我的选择是：

> 可以在前面 Fibonacci 部分稍微出现一次 u/A/B，但之后尽量不要一直用这些符号。

# 六、当前 y 的推导已经基本确定

旧方法：

`Y₀=0`

`Y₁=𝟙`

`Yₙ=𝟙⊕JYₙ₋₁⊕Yₙ₋₂`

逐次递推 n 次，每次处理 n 个元素：

`O(n²)`。

定义：

`Sₙ=F₀+F₁+...+Fₙ₋₁`

可以推得：

`tSₙ=1+Fₙ₋₁+Fₙ`

所以：

`Sₙ(t)=(Fₙ+Fₙ₋₁+1)/t`

这里 `/t` 是**多项式整除**，不是对矩阵 J 做除法。

然后：

`Sₙ=1+tSₙ₋₁+Sₙ₋₂`

代入 J：

`Sₙ(J)=I+JSₙ₋₁(J)+Sₙ₋₂(J)`

因此：

`Yₙ=Sₙ(J)·𝟙`

因为：

`Yₙ`
`=Sₙ(J)·𝟙`
`=𝟙+J[Sₙ₋₁(J)·𝟙]+Sₙ₋₂(J)·𝟙`
`=𝟙+JYₙ₋₁+Yₙ₋₂`

所以闭式成立。

# 七、n=5 的固定例子

`F₄=t⁴+t²+1`

`F₅=t⁵+t`

因此：

`S₅(t)=(F₅+F₄+1)/t`

`=(t⁵+t⁴+t²+t)/t`

`=1+t+t³+t⁴`

所以：

`Y₅=S₅(J)·𝟙`

`=(I+J+J³+J⁴)·𝟙`

最终结果：

`Y₅=10001`

这个 n=5 例子后面一直复用。

# 八、为什么得到 Sₙ(t) 后还没有结束

虽然：

`Yₙ=Sₙ(J)·𝟙`

但如果直接算：

`𝟙, J𝟙, J²𝟙, J³𝟙 ...`

然后按 S 的系数叠加，还是最多 O(n) 次矩阵/向量作用，每次 O(n)，所以还是：

`O(n²)`。

因此接下来要优化的是：

> **如何快速计算 Sₙ(J) 作用到全1向量。**

---

# 九、引入 Laurent 多项式 j(z)

定义：

`j(z)=z⁻¹+1+z`

约定：

`z⁻¹`：左移1位

`1`：保持原位

`z`：右移1位

注意：

> **小写 j(z) 是 Laurent 多项式，不是矩阵 J。**

它只是把 J 的“左移 + 原位 + 右移”结构形式化表示。

因为 GF(2) Frobenius：

`j^(2ᵏ)`

`=(z⁻¹+1+z)^(2ᵏ)`

`=z^(-2ᵏ)+1+z^(2ᵏ)`

所以乘上 `j^(2ᵏ)`，只相当于：

> 左移 2ᵏ + 原位 + 右移 2ᵏ，然后 XOR。

这里一定写：

`j^(2ᵏ)`

不要错误写成有限矩阵：

`J^(2ᵏ)`

直接等于三次平移。

---

# 十、Sₙ(j) 的分治

严格一点的写法是先拆 `S(t)`：

例如 n=8：

`S₈(t)=S低(t)+t⁴S高(t)`

然后 t→j：

`S₈(j)=S低(j)+j⁴S高(j)`

因为：

`j⁴=z⁻⁴+1+z⁴`

所以：

`S₈(j)=S低(j)+(z⁻⁴+1+z⁴)S高(j)`

即：

> 把高半部分左移4位、原位、右移4位，三份 XOR，再与低半部分 XOR。

然后递归拆两半。

不要说：

> “拆到 j¹”

应该说：

> **直到每个子块只剩一个系数。**

递推：

`T(n)=2T(n/2)+O(n)`

所以：

`O(n log n)`。

如果 n 不是 2 的幂，例如 n=11：

> 把 S 的系数末尾补 0 到最近的 2 的幂，例如 16。

补0不改变多项式，而最近的二次幂小于 2n，因此复杂度仍然：

`O(n log n)`。

---

# 十一、n=5 的 S₅(j)

已经固定：

`S₅(t)=1+t+t³+t⁴`

所以：

`S₅(j)=1+j+j³+j⁴`

其中：

`j=z⁻¹+1+z`

`j³=z⁻³+z⁻²+1+z²+z³`

`j⁴=z⁻⁴+1+z⁴`

最后：

`S₅(j)`
`=z⁻⁴+z⁻³+z⁻²+z⁻¹+z+z²+z³+z⁴`

按次数 `-4...4` 写成系数：

`1 1 1 1 0 1 1 1 1`

即：

`111101111`

这个长度9的向量：

> **只是 S₅(j) 的系数序列，不是 Y₅。**

---

# 十二、Sₙ(j) 与真正 Y 的关系

一个非常重要的修正：

不要直接写：

`Yₙ=Sₙ(j)·𝟙`

因为 j 是无限直线上的形式移动，没有考虑有限棋盘边界。

讲稿里目前采用简单说法：

先算中间结果：

`Y′ₙ=Sₙ(j)·𝟙`

这里的“乘”表示：

> 根据 `Sₙ(j)` 的各个 `zᵏ`，把输入向量移动 k 位，然后 XOR。

然后再做：

> **有限棋盘边界反射**

才能得到真正：

`Yₙ=Sₙ(J)·𝟙`

如果以后需要最严谨公式，可以写：

`Yₙ = Foldₙ(Sₙ(j)·𝟙⁰)`

其中 `𝟙⁰` 是棋盘外补0的全1向量，`Foldₙ` 表示有限边界折回。

但视频当前阶段**最好不要主动引入 Fold 符号**，讲“中间结果 + 边界反射”即可。

---

# 十三、n=5 的中间结果与边界

对于：

`S₅(j)=111101111`

`𝟙=11111`

做 GF(2) 卷积，得到：

`Y′₅=1010000000101`

它对应位置 -4 到 8。

拆成：

`101 | 0 | 00000 | 0 | 101`

两个单独的 0 是左右边界位置。

把外侧反射进长度5的棋盘：

左边 `101` 贡献：

`10100`

右边 `101` 贡献：

`00101`

中间本身：

`00000`

XOR：

`00000`
`10100`
`00101`
`-----`
`10001`

所以：

`Y₅=10001`

与直接算：

`S₅(J)·𝟙`

一致。

边界处理扫描 O(n) 个位置，因此：

`O(n)`。

# 十四、y 最终复杂度

当前讲稿最终结论：

计算 `Sₙ(j)`：

`O(n log n)`

与全1向量作用：

`O(n)`

边界反射：

`O(n)`

所以：

`O(n log n)+O(n)+O(n)=O(n log n)`。

# 十五、目前刚刚补充的“卷积”概念

这是当前最新进度，非常重要。

离散卷积定义：

`c[k]=Σᵢ a[i]b[k-i]`

在 GF(2) 中：

`c[k]=⊕ᵢ a[i]·b[k-i]`

直观理解：

> 两个向量相对移动；每个位置把重叠元素逐项相乘，再把结果 XOR。

因此：

> **多项式乘法的系数计算，本质上就是卷积。**

如果：

`A(t)=Σaᵢtⁱ`

`B(t)=Σbⱼtʲ`

那么：

`C(t)=A(t)B(t)`

第 k 项：

`cₖ=Σᵢaᵢbₖ₋ᵢ`

GF(2) 中：

`cₖ=⊕ᵢaᵢbₖ₋ᵢ`

所以视频里可以直接说：

> **多项式乘法 = 系数序列的卷积。**

严格说是“多项式乘法的系数计算等价于卷积”。

---

# 十六、Sₙ(j)、卷积核、输入信号之间的关系

在：

`Sₙ(j)=Σaᵣzʳ`

中，系数序列 `aᵣ` 描述：

> 输入应该移动多少位并叠加。

从“算子”的角度：

* `Sₙ(j)` 的系数序列可以看成**卷积核 / filter**
* `𝟙` 看成**输入信号**

于是：

`Y′ = Sₙ(j) * 𝟙`

但是卷积满足交换律：

`a*b=b*a`

所以为了分析全1这个特殊情况，也可以反过来看：

* `Sₙ(j)` 系数序列作为输入
* `111...1` 作为卷积核

这样每个输出就是：

> `Sₙ(j)` 中一段连续系数的 XOR。

这正是为什么可以 O(n)。

# 十七、“窗口”这个词的定位

“窗口”不是卷积定义中的一个独立数学对象。

它只是指：

> 计算某一个输出位置时，当前与另一序列重叠的连续部分。

例如：

`S₅(j)=111101111`

与长度5的全1卷积时，参与 XOR 的连续部分依次可以看成：

`1`
`11`
`111`
`1111`
`11110`
`11101`
`11011`
`10111`
`01111`
`1111`
`111`
`11`
`1`

但视频当前倾向于：

> **尽量少用“窗口”“滑动窗口”这些术语。**

可以直接说：

> “当前参与异或的连续部分”。

# 十八、前缀异或到底是什么

前缀异或**不是卷积本身**。

它是：

> **针对“其中一个序列全为1”这种特殊卷积的快速计算方法。**

对于一个序列：

`A`

先算前缀 XOR：

`P[k]=A[0]⊕...⊕A[k]`

那么连续区间：

`A[L]⊕...⊕A[R]`

可以 O(1) 得到：

`P[R]⊕P[L-1]`

所以：

> 与全1向量卷积，可以用前缀异或在线性时间计算。

当前讲稿里准备只用非常短的两句话介绍：

> 把这个概念应用到 y 的计算上，就是：**将 `Sₙ(j)` 的系数序列与全1向量做 GF(2) 卷积。**

> 由于其中一个向量是全1，**卷积结果可以用前缀异或在线性时间内快速计算。**

# 十九、一个已经确认过的简单卷积例子

如果：

`Sₙ(j)=1+z`

`𝟙=11111`

按照此前约定：

`1` = 原位

`z` = 右移1位

所以：

```text
111110
011111
------
100001
```

即：

`(1+z)·11111=100001`

这里准确含义是：

> `Sₙ(j)` 中的每一项规定输入向量移动多少位，把这些移动后的输入向量 XOR。

不是普通的“两个二进制向量相乘”。

上下两行交换没有区别，因为 XOR/卷积满足交换性。

# 二十、当前正在进入 Karatsuba

最新讲稿大致是：

> 下面我们介绍 Karatsuba 快速多项式乘法。它利用分治的原理加速多项式乘法运算，也是我们后续优化时间复杂度的重要手段。

> Karatsuba 的原理其实特别简单：将两个多项式各拆分成两半，把原本需要的四次乘法减少为三次。然后不断递归地拆分多项式，使时间复杂度从原来的 `O(n²)` 降低到 `O(n^log₂3)≈O(n^1.585)`。

> 因此，Karatsuba 是一种分治式快速多项式乘法。聪明的你一定发现了，**多项式乘法中各项系数的计算，本质上就是卷积，因此 Karatsuba 也可以用来加速一般卷积。**

这段已经确认概念正确。

---

# 二十一、Karatsuba 的核心公式，接下来大概率要讲

两个多项式：

`A=A₀+tᵐA₁`

`B=B₀+tᵐB₁`

普通展开需要：

`A₀B₀`

`A₀B₁`

`A₁B₀`

`A₁B₁`

共4次子乘法。

Karatsuba 改成：

`P₀=A₀B₀`

`P₂=A₁B₁`

`P₁=(A₀+A₁)(B₀+B₁)`

GF(2) 中中间部分：

`A₀B₁+A₁B₀=P₁+P₀+P₂`

因此：

`AB=P₀+tᵐ(P₁+P₀+P₂)+t²ᵐP₂`

只需要3次一半规模的乘法。

递推：

`T(n)=3T(n/2)+O(n)`

所以：

`T(n)=O(n^log₂3)≈O(n^1.585)`。

---

# 二十二、Karatsuba 和卷积的准确关系

不要说：

> “Karatsuba 就是卷积。”

准确说：

> **Karatsuba 是快速多项式乘法算法。**

而：

> **多项式乘法的系数计算本质上就是卷积。**

因此：

> **Karatsuba 也可以看成一种快速计算一般卷积的方法。**

另外，全1卷积已经能利用特殊结构做到：

`O(n)`

所以 y 这里**不需要 Karatsuba**。

Karatsuba 主要是后面遇到：

> 两个一般多项式 / 两个一般系数序列

进行乘法时使用。

# 二十三、后续预计继续讲的内容

Karatsuba 后面会继续进入：

Half-GCD、q/g、z/gen、Toeplitz 求解等。

q/g 预计要讲：

普通欧几里得 / 长除法
→ Bézout
→ 多项式反转
→ 级数求逆
→ Newton
→ 快速除法
→ Half-GCD

GF(2) Newton 求逆有一个漂亮性质：

如果：

`AG=1 mod tᵏ`

则可以利用平方使精度翻倍。

Half-GCD 本质上是：

> **递归压缩多项式 Euclid 的多步变换。**

不要把 Half-GCD 解释成简单“只算高位”。

目标复杂度在使用 Karatsuba 乘法后大约：

`O(n^1.585)`。

# 二十四、g、秩亏、x 的后续记号

后面尽量采用：

`d=deg(g)`

表示秩亏 / 零空间维数。

秩：

`r=n-d`

如果可解，则静默操作模式数：

`2^d`

以前代码/旧稿里 `r`、`d` 有过不同含义，因此后面一定要注意不要混。

还有一个特殊性质：

`deg(g)=n`

只在：

`n=0` 或 `n=4`

成立。

这里不是说“解唯一”。

n=4 时反而是：

`d=4`

rank=0。

# 二十五、x 阶段后续复杂度

旧逆推解 x 的复杂度粗略写成：

`O(nd)`

更准确一些可以理解为：

`O((n-d)d)=O(rd)`

最坏情况 d 和 n-d 都是 Θ(n)，所以仍可 O(n²)。

后续算法使用：

> triangular Toeplitz solve / Newton / Karatsuba

把最坏情况压到大约：

`O(n^1.585)`。

# 二十七、一些已经确定不要再反复纠结的问题

旧方法里有：

`p=f+c`

又因为：

`f(H)=0`

所以：

`p(H)=c(H)`

这条没有问题。

扩展 Euclid 的一般形式可以写：

`sf+qc=g`

可逆时：

`g=1`

得到：

`cq=1 mod f`

旧视频默认 `g=1` 时把 `q(H)y` 直接当 x，有上下文，因此无需反复纠正。

# 二十八、整体算法目标复杂度

最终希望视频给出大致这样的链条：

`f/c`：O(n)

`y`：O(n log n)

一般多项式乘法：Karatsuba O(n^1.585)

`q/g`：Half-GCD + Karatsuba，约 O(n^1.585)

`z/gen`：结构化 Laurent / Karatsuba，约 O(n^1.585)

奇异情况下 `x`：Toeplitz / 快速多项式方法，最坏约 O(n^1.585)

所以：

> **首行求解核心约 O(n^log₂3)≈O(n^1.585)。**

但如果最后要求输出完整 n×n 棋盘：

> 输出本身仍然 Θ(n²)。

# 二十九、代码优化项目背景，若新会话涉及代码需要知道

项目版本长期为：

`diandeng10_a_faster2_png_Hxx.pas`

`diandeng10_b_faster2_png_Hxx.pas`

其中：

* a：Boolean 实现
* b：LongWord / bitwise 实现

**强约束：a/b 必须数学算法完全一致。**

b 只能是相同算法的 LongWord 位并行实现，不能：

* 另换数学算法
* 根据 n 选择不同算法
* 为 b 单独走特殊路径

不能用类似：

`{$optimization on}`

这种编译器优化冒充算法优化。

允许 inline。

尽量做：

> 小改动、可追踪、每一版明确一个优化点。

主要 benchmark 阶段：

`mak / q / z / x / gen`

后五阶段都可以优化，但必须保证正确性和没有明显回退。

目前 H 系列已经推进到 H70+，上一阶段对 H73/H75/H76 仍在继续研究。新视频主要解释的是这些版本背后的数学思想，而不是逐版本流水账。
