# 四、整个算法当前应使用的数学关系

工作域：

`GF(2)`

所以：

`加法 = 减法 = XOR`

核心扩展欧几里得关系：

`sf + qc = g`

其中：

`g = gcd(f,c)`

因此：

`qc ≡ g (mod f)`

注意绝不能写成：

`qc=g`

或：

`q=g/c`

因为未代入 H 时 `f≠0`。

在点灯游戏中代入 H：

`s(H)f(H)+q(H)c(H)=g(H)`

由于：

`f(H)=0`

所以：

`q(H)c(H)=g(H)`

因此 q 本质是扩展 Euclid 得到的 Bézout 系数。

如果 `g=1`，q 才可理解成 c 模 f 的逆。

# 五、Karatsuba 已经确定的讲法

拆：

`A=A₀+tᵐA₁`

`B=B₀+tᵐB₁`

普通需要4次半规模乘法。

Karatsuba：

`P₀=A₀B₀`

`P₂=A₁B₁`

`P₁=(A₀+A₁)(B₀+B₁)`

GF(2) 中：

`A₀B₁+A₁B₀=P₁+P₀+P₂`

所以：

`AB=P₀+tᵐ(P₁+P₀+P₂)+t²ᵐP₂`

递推：

`T(n)=3T(n/2)+O(n)`

因此：

`O(n^log₂3)≈O(n^1.585)`

准确措辞：

**Karatsuba是快速多项式乘法。多项式乘法的系数计算本质是卷积，因此Karatsuba也可以快速计算一般卷积。**

不要直接说：

“Karatsuba就是卷积。”

---

# 六、快速多项式除法当前已经基本写完

目标：

`A=BQ+R`

普通长除法从最高次项开始逐项消元，最坏 `O(n²)`。

快速除法核心是将除法变成：

**反转 + 求逆 + 多项式乘法**

设：

`deg(A)=m`

`deg(B)=n`

`d=m-n`

反转：

`Aᴿ=tᵐA(1/t)`

同理定义 `Bᴿ、Qᴿ`。

有：

`Aᴿ ≡ BᴿQᴿ mod t^(d+1)`

因此：

`Qᴿ ≡ Aᴿ(Bᴿ)⁻¹ mod t^(d+1)`

所以快速除法五步：

1. 反转 A、B；
2. 求 `(Bᴿ)⁻¹`；
3. `Aᴿ(Bᴿ)⁻¹` 得 Qᴿ；
4. Qᴿ 反转回来得 Q；
5. `R=A+BQ`。

反转 `O(n)`。

乘法使用 Karatsuba：

`O(n^1.585)`

所以剩下关键是逆能不能同样做到 `O(n^1.585)`。

注意：

B 是首一多项式，因此 Bᴿ 的常数项为1，所以形式幂级数逆存在。

---

# 七、Newton求逆已经确定

这里要求：

`G=P⁻¹ mod tⁿ`

P 实际就是前面的 Bᴿ，常数项1。

设旧的近似逆为：

`G'`

精度 k：

`PG' ≡1 mod tᵏ`

写成：

`PG'=1+E`

其中：

`E=tᵏF`

平方：

`(PG')²`

`=P²(G')²`

`=(1+E)²`

GF(2) Frobenius：

`(1+E)²=1+E²`

所以：

`P²(G')²=1+t²ᵏF²`

因此：

`P²(G')² ≡1 mod t²ᵏ`

定义新逆：

`G=P(G')² mod t²ᵏ`

则：

`PG=P²(G')²≡1 mod t²ᵏ`

所以精度：

`k → 2k`

即：

`1 → 2 → 4 → 8 → ... → n`

GF(2) 中 `(G')²` 只需把所有指数乘2，属于线性操作。

真正昂贵的是：

`P(G')²`

使用 Karatsuba。

Newton 总复杂度：

`O(1^α+2^α+4^α+...+n^α)`

其中：

`α=log₂3≈1.585`

因为：

`2^α=3`

这是等比级数：

`1+3+9+...`

所以：

`O(n^α)=O(n^1.585)`

因此快速除法整体也能做到：

`O(n^1.585)`。

# 八、关于“快速除法直接放进普通 Euclid”的准确说法

不要绝对说：

“用了快速除法，Euclid就变成 O(n^2.585)。”

准确说法应是：

> 如果仍然保持普通Euclid一步一步的结构，并且每一步都机械地按照当前多项式完整规模调用 `O(k^1.585)` 的通用快速除法，那么粗略的最坏求和可能达到：
>
> `Σ k^1.585 = O(n^2.585)`
>
> 因此，仅仅加速单次除法，并不能直接得到一个 `O(n^1.585)` 的完整GCD算法。

实际代码对于 `Q=t` 这种短商当然不会非得启用 Newton。

普通经典 Euclid 整体平方级更自然的解释是：

最坏次数逐次下降：

`n,n-1,n-2,...`

当前步主要扫描当前长度，所以：

`n+(n-1)+...+1=O(n²)`

# 九、Half-GCD 当前使用的符号约定

一定继续采用**行向量右乘矩阵**，不能和列向量版本混用。

一次 Euclid：

`A=QB+R`

GF(2)：

`R=A+QB`

定义：

`E(Q)=[0,1;1,Q]`

若：

`V=(A,B)`

则：

`V E(Q)=(B,A+BQ)=(B,R)`

所以：

`V1=V0E(Q1)`

`V2=V1E(Q2)=V0E(Q1)E(Q2)`

一般：

`Vk=V0E(Q1)E(Q2)...E(Qk)`

累计变换矩阵记作：

`M=E(Q1)E(Q2)...E(Qk)`

不要把初始向量叫 M。

推荐统一：

* `V0,V1,...`：行向量/当前余数对；
* `E(Qi)`：一步 Euclid 的变换矩阵；
* `M`：很多步累计变换矩阵。

如果：

`M=[U,V;X,Y]`

则：

`(A,B)M=(AU+BX,AV+BY)`

所以一个代表很多步 Euclid 的累计矩阵，一旦求出，只需要常数次大多项式乘法即可作用到完整 A、B。

这就是 Karatsuba 可以发挥作用的位置。

# 十一、Half-GCD 的 n=16 教学演示

为了教学，可以这样理解：

原始 A、B：

`11100101 00101110`

`01101101 00110111`

先只取高8位：

`A高=11100101`

`B高=01101101`

这个较小问题得到：

`Q1高=t`

`Q2高=t`

`Q3高=t+1`

正好对应完整问题的前三步。

于是：

`M高=E(Q1高)E(Q2高)E(Q3高)`

得到：

`[t,t²+t+1;t²+1,t³+t²+1]`

将这个 M高 一次作用回完整 A、B：

`V3=V0M高`

直接得到完整的：

`R2,R3`

此时：

`deg(R3)=11`

还没有 `<8`

所以对完整的：

`R2,R3`

做一次真正的精确除法：

`Q4=t`

`R4=R2+tR3`

这里使用快速多项式除法。

然后再处理：

`R3,R4`

的适当高次部分。

这个例子中，根据当前截断位置，需要去掉 R3、R4 的低5位：

`R3高=1011100`

`R4高=0100100`

由此得到第二批：

`Q5高=t`

`Q6高=t`

`Q7高=t+1`

第二批累计矩阵：

`M高'=E(Q5高)E(Q6高)E(Q7高)`

这个例子中恰好：

`M高'=M高`

只是因为：

`Q1,Q2,Q3`

恰好和：

`Q5,Q6,Q7`

相同。

**这是巧合，不是 Half-GCD 的规律。**

最后：

`V7=V4M高'`

其中：

`V4=(R3,R4)`

使用的是完整 R3、R4。

得到：

`R6,R7`

且：

`deg(R7)<8`

# 十二、Half-GCD 最核心的理解

普通 Euclid：

`Q1`

`Q2`

`Q3`

`Q4`

`Q5`

`Q6`

`Q7`

全部在完整问题上顺序执行。

Half-GCD 将其重新组织成：

`较小的高位问题`

→ 一批操作 `Q1,Q2,Q3`

→ 合成累计矩阵 M1

→ 一次作用回完整 A、B

→ 一次完整精确除法 Q4

→ 第二个较小高位问题

→ 一批操作 `Q5,Q6,Q7`

→ 合成累计矩阵 M2

→ 一次作用回完整 R3、R4。

抽象的一层结构：

`Half-GCD(n/2)`

→ 累计矩阵作用到完整问题

→ 一次快速精确除法

→ `Half-GCD(约n/2)`

→ 矩阵作用与合并。

所以：

`T(n)=2T(n/2)+O(M(n))`

Karatsuba：

`M(n)=O(n^1.585)`

因此：

`T(n)=O(n^1.585)`。

矩阵本身不是加速来源。

真正加速来自：

> 将很多顺序 Euclid 操作压缩为少数大多项式乘法，再用 Karatsuba 快速完成；两个递归块之间需要一次快速多项式除法精确连接。

# 十三、Half-GCD 与 Fast-GCD / Fast-XGCD 的区别

这是当前最后正在讨论、下一会话很可能继续的问题。

标准意义：

**Half-GCD(n)**

输入规模约 n，只负责将第二个多项式的次数降低到大约 `n/2` 以下，然后返回。

它不负责一路算到最终 gcd。

当前16位例子：

`V0 → V7`

且：

`deg(R7)<8`

这一整段就是一次：

`Half-GCD(16)`

不是“Half-GCD(8前)”之类。

`Half-GCD(16)` 内部可以包含两个约8规模的 Half-GCD 子问题，中间加一次精确除法。

如果输入本来是32规模：

`Half-GCD(32)`

内部大致包含两个：

`Half-GCD(约16)`

以及中间精确除法和矩阵合并。

但是：

`Half-GCD(32)`

不是为了“把16的问题算到最终 gcd”。

32表示的是**输入规模**。

---

完整求 gcd 的外层算法可以称：

**Fast-GCD**

它不断利用 Half-GCD 将当前问题缩小：

`16`

→ Half-GCD

`约8`

→ 继续

`约4`

→ …

→ 最终 gcd。

如果最终还需要：

`sf+qc=g`

则完整算法更准确叫：

**Fast-XGCD / Fast Extended GCD**

它在继续缩小问题的同时，还累积 Half-GCD 返回的变换矩阵，从而最终得到 s、q。

当前用户的一个疑问是：

> Fast-GCD 和 Half-GCD 看上去很相似。

目前已经明确：

**它们内部使用的数学操作确实非常相似，区别主要是停止条件和目标。**

Half-GCD：

> 只降到一半就返回。

Fast-GCD：

> Half-GCD 返回后继续，直到最后余数为0。

同时注意：

**中间余数 R 不等于 gcd。只有最后一个非零余数才是 gcd。**

# 十六、Toom-Cook / FFT 已经确认的理论结论

后面视频还会讲。

固定拆成 k 块的 Toom-Cook：

需要：

`2k-1`

个约 `n/k` 的子乘法。

递推：

`T(n)=(2k-1)T(n/k)+O(n)`

所以：

`T(n)=O(n^(logₖ(2k-1)))`

例如：

* Toom-2 / Karatsuba：`O(n^1.585)`
* Toom-3：约 `O(n^1.465)`
* Toom-4：约 `O(n^1.404)`
* Toom-5：约 `O(n^1.365)`
* Toom-6：约 `O(n^1.338)`

k 固定但越来越大时，指数趋近1。

不能因此直接说无限阶 Toom-Cook 就是 O(n)，因为 k 增大时求值/插值开销和常数也增长。

FFT 型多项式乘法理论可到：

`O(n log n)`

但本项目是 GF(2)，不能直接套普通复数 FFT，需要扩域、additive FFT、打包到合适环等。因此视频中最好说：

> 更进一步，FFT一类快速多项式乘法可以把理论复杂度继续降低到接近 O(n log n)。

# 十七、与实际 H75 源码的对应关系

虽然视频不应逐源码讲，但算法必须能和真实实现对应。

H75 里大致关系：

`HPHalfGCDCore`
→ 调用 `HPDivRem`
→ 大规模时进入 `HPDivRemFast`
→ 快速除法内部调用 `HPInvSeries`
→ Newton/级数求逆内部使用快速多项式乘法。

也就是说真实层次是：

**Karatsuba**
→ Newton求逆
→ 快速除法
→ Half-GCD

而 Half-GCD 自己在累计变换矩阵的应用/合并中也使用快速多项式乘法。

完整扩展 gcd 的实际实现由 `HPXGCDCore` 组织：

Half-GCD 取得一批变换
→ 作用到完整多项式
→ 快速除法
→ 递归
→ 合并 Bézout 变换

最终得到：

`g,s,q`

所以视频中的“Fast-XGCD = 使用 Half-GCD 一直做到最终 gcd/Bézout 系数”与实际程序数学结构是一致的，但不必完全复制源码控制流程。

# 十八、整个 H75 算法复杂度背景

当前核心流程：

`mak → q → z → x → gen`

数学关系大致：

`f/c、y → q/g → z → x`

当前目标复杂度：

* f/c：GF(2) Fibonacci doubling，`O(n)`
* y：H75 已可通过 S 的直接倍增做到 `O(n)`；旧中间版本曾是 `O(n log n)`
* q/g：Half-GCD + 快速除法 + Karatsuba，约 `O(n^1.585)`
* z/gen：结构化 Laurent/Karatsuba，约 `O(n^1.585)`
* 奇异 x：Toeplitz/Newton/Karatsuba，约 `O(n^1.585)`
* 首行核心整体约 `O(n^1.585)`
* 全棋盘显式输出仍为 `Θ(n²)`
